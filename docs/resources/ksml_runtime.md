# axual_ksml_runtime (Resource)

A KSML runtime registers a KSML provisioner on an Instance-Cluster, so KSML applications can be deployed to it.

## Usage
- An `axual_ksml_runtime` registers an existing KSML provisioner on an Instance-Cluster. The provisioner must already run and be reachable from Platform Manager at `url`; Terraform does not install it.
- Once registered, the KSML runtime can be referenced from an `axual_application_deployment` of a `Ksml` application through its `target_id`. The deployment runs against the Kafka cluster the KSML runtime is registered on.
- `instance_id` and `cluster_id` identify where the KSML runtime is registered. Changing either one forces the resource to be replaced.
- `schema_registries` lists the registries the KSML applications on this KSML runtime read schemas from. Removing the block again clears the stored list.
- `owners` is the id of the Group that owns the KSML runtime. Its members can edit the KSML runtime, but owning it does not allow deploying to it. Only a Tenant Admin or a Platform Admin can change the owner.
- `authorized_groups` lists the Groups that may deploy KSML applications to the KSML runtime, and a Group that is not listed cannot select it as a deployment target. **A KSML runtime without authorized Groups accepts no deployments, from the owner Group either**, so add the Group of every application that deploys to it. Leave `authorized_groups` out to keep the Groups the KSML runtime has; `authorized_groups = []` removes all of them. A replaced KSML runtime (a new `name`, `instance_id` or `cluster_id`) gets only the Groups in the configuration, so none when `authorized_groups` is left out. A Group cannot be removed while it has a running KSML deployment on the KSML runtime.
- Platform Manager does not allow renaming a KSML runtime. Changing `name` destroys the KSML runtime and creates a new one, which fails while a KSML deployment still targets it: move the deployments to another KSML runtime, or remove them, first.
- A KSML runtime cannot be destroyed while a KSML deployment targets it, whatever the state of the deployment. To move its deployments and remove the KSML runtime, use two applies: first change the `target_id` of the deployments and keep the KSML runtime in the configuration, then remove it. In one apply, Terraform deletes the KSML runtime before it moves the deployments, and Platform Manager refuses that.
- A KSML Provisioner that was configured before Platform Manager had KSML runtimes is a KSML runtime without an owner Group. Import it and set `owners`; the first apply then needs a Tenant Admin or a Platform Admin.
- Currently, a data source for `axual_ksml_runtime` is not supported.

## Prerequisites

- KSML must be enabled for the tenant, or the API refuses the create with "KSML is disabled for this tenant".
- You can register more than one KSML runtime per Instance-Cluster combination. The name must be unique within your tenant, ignoring case.

## Platform Manager version

- Platform Manager 17.0.0 or later.

## Required Roles
- TENANT_ADMIN or PLATFORM_ADMIN to register or delete a KSML runtime, and to change its owner
- A member of the owner Group can update the other attributes

## Schema

### Required

- `cluster_id` (String) The Uid of the Cluster this KSML runtime belongs to.
- `instance_id` (String) The Uid of the Instance this KSML runtime belongs to.
- `name` (String) Human-readable name of the KSML runtime. Must be between 3 and 50 characters, and unique within your tenant, ignoring case. Platform Manager does not allow renaming, so changing the name destroys and re-creates the KSML runtime.
- `owners` (String) The id of the Group that owns the KSML runtime, for example `data.axual_group.platform_team.id`. Members of the owner Group can edit the KSML runtime, but owning it does not allow deploying to it: add the Group to `authorized_groups` for that. Only a Tenant Admin or a Platform Admin can change the owner.
- `url` (String) Base URL of the KSML provisioner, e.g. `https://ksml.example.com`. Must be 1 to 255 characters, without white space around it.

### Optional

- `authorized_groups` (Set of String) The ids of the Groups that may deploy KSML applications to the KSML runtime. Leave it out to keep the Groups the KSML runtime has; `authorized_groups = []` removes all of them. A replaced KSML runtime (a new `name`, `instance_id` or `cluster_id`) gets only the Groups in the configuration. **A KSML runtime without authorized Groups accepts no deployments, from the owner Group either.** A Group cannot be removed while it has a running KSML deployment on this KSML runtime.
- `description` (String) A short description of the KSML runtime. Must be 1 to 255 characters. Leave it out for none.
- `schema_registries` (Attributes List) Schema registries the KSML applications on this KSML runtime read schemas from. Leave it out for none: an empty list is refused. (see [below for nested schema](#nestedatt--schema_registries))

## Example Usage

```hcl
resource "axual_ksml_runtime" "example_ksml_runtime" {
  instance_id = data.axual_instance.testinstance.id
  cluster_id  = "<CLUSTER UID>"
  name        = "Example KSML runtime"
  owners      = data.axual_group.platform_team.id
  description = "KSML runtime for the analytics workloads"
  url         = "https://ksml.example.com"

  # The Groups that may deploy KSML applications to this KSML runtime. Without it, nobody can.
  authorized_groups = [data.axual_group.data_engineering.id]

  schema_registries = [
    {
      type = "CONFLUENT"
      url  = "https://apicurio.example.com/apis/ccompat/v7"
    },
  ]
}

resource "axual_application_deployment" "example_ksml_deployment" {
  environment     = axual_environment.development.id
  application     = axual_application.example_ksml_application.id
  target_id       = axual_ksml_runtime.example_ksml_runtime.id
  definition      = file("definitions/ksml-definition.yaml")
  deployment_size = "S"
  restart_policy  = "on_exit"
}
```

## Import

Import is supported using the following syntax. Because Platform Manager finds a KSML runtime through the Instance-Cluster it is registered on, the import identifier is the instance uid, the cluster uid and the KSML runtime uid separated by `/`:

```shell
terraform import axual_ksml_runtime.<LOCAL NAME> <INSTANCE UID>/<CLUSTER UID>/<KSML RUNTIME UID>
terraform import axual_ksml_runtime.example_ksml_runtime 9b4b1e3a1e2f4b5f8a1c0d2e3f4a5b6c/3f2a1b0c9d8e7f6a5b4c3d2e1f0a9b8c/7c6b5a4938271605f4e3d2c1b0a99887
```
