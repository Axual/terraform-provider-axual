# axual_flink_cluster (Resource)

A Flink Cluster registers a Ververica Platform namespace on an Instance-Cluster, so Flink SQL applications can be deployed to it.

## Usage
- An `axual_flink_cluster` registers an existing Ververica Platform namespace on an Instance-Cluster. The namespace, workspace and deployment target must already exist in Ververica Platform; Terraform does not create them.
- Once registered, the Flink Cluster can be referenced from an `axual_application_deployment` of a `FLINK_SQL` application through its `target_id`.
- `instance_id` and `cluster_id` identify where the Flink Cluster is registered. Changing either one forces the resource to be replaced.
- `api_token` is a namespace-scoped Ververica API token. It is marked sensitive, is never shown in plan output or logs, and is not returned by the API, so it is kept as written in the Terraform state and configuration.
- `schema_registries` lists the registries a Flink SQL job reads schemas from. It is required for jobs over AVRO topics: the platform injects the registry url into the generated table DDL, and a job using `'value.format' = 'avro-confluent'` takes the first `CONFLUENT`-type entry in the list. Removing the block again clears the stored list.
- `owners` is the id of the Group that owns the Flink Cluster. Its members can edit the Flink Cluster, but owning it does not allow deploying to it. Only a Tenant Admin can change the owner.
- `authorized_groups` lists the Groups that may deploy Flink SQL applications to the Flink Cluster, and a Group that is not listed cannot select it as a deployment target. **A Flink Cluster without authorized Groups accepts no deployments, from the owner Group either**, so add the Group of every application that deploys to it. Leave `authorized_groups` out to keep the Groups the Flink Cluster has; `authorized_groups = []` removes all of them. A Group cannot be removed while it has a running Flink SQL deployment on the Flink Cluster.
- Platform Manager does not allow renaming a Flink Cluster. Changing `name` destroys the Flink Cluster and creates a new one, which fails while a `FLINK_SQL` deployment still targets it: remove the deployments first.
- Currently, a data source for `axual_flink_cluster` is not supported.

## Prerequisites

- The instance must have Flink enabled, or the API refuses the create with "Flink is not enabled for this instance".
- You can register more than one Flink Cluster per Instance-Cluster combination. The name must be unique within your tenant.
- Both create and update validate the connection live against Ververica Platform, so a wrong `namespace`, `workspace` or `deployment_target` fails the apply rather than the first deployment: expect "The provided namespace is invalid" or "The provided deployment-target: `<name>` was not found". An unreachable `url` or a rejected `api_token` fails the same way.

## Platform Manager version

- Platform Manager 17.0.0 or later.

- TENANT_ADMIN

## Example Usage

```hcl
resource "axual_flink_cluster" "example_flink_cluster" {
  instance_id       = data.axual_instance.testinstance.id
  cluster_id        = "<CLUSTER UID>"
  name              = "Example Flink Cluster"
  owners            = data.axual_group.platform_team.id
  description       = "Ververica Platform namespace used for Flink SQL applications"
  url               = "https://vvp.example.com"
  workspace         = "defaultworkspace"
  namespace         = "default"
  deployment_target = "default-target"
  api_token         = "<VERVERICA API TOKEN>"

  # The Groups that may deploy Flink SQL applications to this Flink Cluster. Without it, nobody can.
  authorized_groups = [data.axual_group.data_engineering.id]

  schema_registries = [
    {
      type = "CONFLUENT"
      url  = "https://apicurio.example.com/apis/ccompat/v7"
    },
  ]
}
```

For a full example of a Flink SQL setup, check https://github.com/Axual/terraform-provider-axual/tree/master/examples/flink-sql.

## Import

Import is supported using the following syntax. Because a Flink Cluster's uid is only unique within the Instance-Cluster it is registered on, the import identifier is the instance uid, the cluster uid and the Flink Cluster uid separated by `/`:

```shell
terraform import axual_flink_cluster.<LOCAL NAME> <INSTANCE UID>/<CLUSTER UID>/<FLINK CLUSTER UID>
terraform import axual_flink_cluster.example_flink_cluster 9b4b1e3a1e2f4b5f8a1c0d2e3f4a5b6c/3f2a1b0c9d8e7f6a5b4c3d2e1f0a9b8c/7c6b5a4938271605f4e3d2c1b0a99887
```

After importing, run `terraform plan` and add the `api_token` to your configuration: the API does not return it, so it cannot be read back into state.
