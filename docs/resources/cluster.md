# axual_cluster (Resource)

A Cluster is a Kafka cluster that Platform Manager governs. Add it to an Instance with `axual_instance` before topics can be created on it. The broker connection details and credentials are stored in Vault.

## Usage
- An `axual_cluster` registers a Kafka cluster with Platform Manager. To use it, add it to an Instance with `axual_instance`, and give the Instance-Cluster a schema registry with `axual_instance_cluster`.
- `broker` is how Platform Manager itself connects to the brokers, to create topics and ACLs. The client must be allowed to do that, for example a superuser.
  - For `MTLS`, set `certificate` and `private_key` (PEM). For `SASL/...`, set `username` and `password`.
  - `certificate`, `private_key` and `truststore` take PEM. Platform Manager keeps them base64-encoded, the way the Self-Service UI sends them, so the provider does the encoding. An already base64-encoded value is also accepted.
- The private key and the passwords are stored in Vault. Platform Manager never returns them, so they are sent from the configuration on every update and cannot be imported.
- `shared` and `provider_type` cannot change: changing either one replaces the Cluster.
- A Tenant Admin keeps the default `shared = false`. Only a Super Admin can change or delete a shared Cluster.
- Platform Manager refuses a change of `topic_pattern`, `group_pattern` or `transactional_pattern` once topics exist on the Cluster.
- A Cluster can only be deleted when no Instance uses it.

## Prerequisites
- With `ssl_auth_mode = "fullChainCertificate"`, the brokers must run the Axual principal builder, and an Instance on the Cluster needs `ca_certificates`.
- Platform Manager connects to the brokers when the Cluster is created. A bootstrap host it cannot reach fails the apply. Some Platform Manager versions do not refuse credentials the brokers reject; they only log a warning, so check that a topic can be created.

## Platform Manager version
- Platform Manager 16.0.0 or later. `provider_type = "strimzi"` needs the next Platform Manager release after 16.0.x.
- Some Platform Manager versions delete the schema registry of the Instance-Clusters when a Cluster is renamed. The next `terraform apply` configures it again from `axual_instance_cluster`.

## Required Roles
- TENANT_ADMIN, or SUPER_ADMIN for a shared Cluster

## Schema

### Required

- `broker` (Attributes) How Platform Manager connects to the brokers. Platform Manager checks the connection when the Cluster is created. (see [below for nested schema](#nestedatt--broker))
- `name` (String) The name of the Cluster, unique in the tenant. Must be between 3 and 50 characters: letters, digits, `.`, `-` and `_`.
- `provider_type` (String) How Platform Manager manages the Cluster: `apache-kafka` or `strimzi`. Changing it creates a new Cluster.

### Optional

- `billing_cloud_enabled` (Boolean) Whether usage of the Cluster is billed as cloud usage. Default `false`.
- `bootstrap_urls_by_authentication` (Map of String) The bootstrap servers applications use, per authentication method: `MUTUAL_TLS` and `SCRAM_SHA_512`.
- `description` (String) A short description of the Cluster. Must be at most 200 characters.
- `group_pattern` (String) How a consumer group id is made on the Cluster, for example `{tenant}-{instance}-{environment}-{group}`.
- `kafka_listeners` (Map of String) Listeners of the Cluster, by name.
- `kafka_version` (String) The Kafka version of the Cluster, for information.
- `location` (String) Where the Cluster runs, for example `Amsterdam`. Must be at most 50 characters.
- `oauth_principals_prefix` (String) Prefix of OAuth principals on the Cluster. Platform Manager refuses a change while OAuth principals exist.
- `shared` (Boolean) Whether the Cluster is shared by all tenants. A shared Cluster can only be changed and deleted by a Super Admin, so a Tenant Admin keeps the default `false`. Changing it creates a new Cluster.
- `ssl_auth_mode` (String) How the brokers name an SSL client: `certificate` (the subject) or `fullChainCertificate` (the subjects of the whole chain, from the Axual principal builder). With `fullChainCertificate`, an Instance on this Cluster needs `ca_certificates`.
- `strimzi` (Attributes) The Strimzi Kafka cluster behind the Cluster. Required when `provider_type` is `strimzi` (Platform Manager 16.1.0 or later). (see [below for nested schema](#nestedatt--strimzi))
- `topic_pattern` (String) How a topic name is made on the Cluster, for example `{tenant}-{instance}-{environment}-{topic}`. Platform Manager refuses a change once topics exist. A Cluster can only serve several environments of one Instance when the pattern contains `{environment}`.
- `transactional_pattern` (String) How a transactional id is made on the Cluster, for example `{tenant}-{instance}-{environment}-{transactional.id}`.

### Read-Only

- `id` (String) Cluster unique identifier

### Nested Schema for `broker`

Required:

- `bootstrap_servers` (String) Bootstrap servers Platform Manager connects to, for example `kafka-0.example.com:9093`.
- `protocol` (String) How Platform Manager authenticates: `MTLS`, `SASL/PLAIN`, `SASL/SCRAM-SHA-256` or `SASL/SCRAM-SHA-512`.

Optional:

- `ca_validation` (Boolean) Whether Platform Manager checks that `truststore` holds a valid CA. Default `true`.
- `certificate` (String) PEM client certificate (chain) for `MTLS`. Requires `private_key`.
- `password` (String, Sensitive) SASL password. Platform Manager never returns it, so it is not read back and cannot be imported. This field is Sensitive.
- `private_key` (String, Sensitive) PEM private key of `certificate`. Platform Manager never returns it, so it is not read back and cannot be imported. This field is Sensitive.
- `security_protocol` (String) Kafka security protocol for SASL: `SASL_SSL` or `SASL_PLAINTEXT`. Platform Manager uses `SASL_SSL` when it is not set.
- `truststore` (String) PEM CA certificates that sign the broker certificates.
- `username` (String) SASL username. Requires `password`.

### Nested Schema for `strimzi`

Required:

- `cluster_name` (String) The `strimzi.io/cluster` name of the Kafka cluster.
- `namespace` (String) The Kubernetes namespace of the Kafka cluster.

- `provisioner_password` (String, Sensitive) Password for the Strimzi provisioner. Platform Manager never returns it. This field is Sensitive.

- `provisioner_username` (String) Username for the Strimzi provisioner. Requires `provisioner_password`.

## Example Usage

```hcl
resource "axual_cluster" "production" {
  name          = "production-ams"
  description   = "Production Kafka cluster in Amsterdam"
  location      = "Amsterdam"
  provider_type = "apache-kafka"
  broker = {
    bootstrap_servers = "kafka-0.example.com:9093"
    protocol          = "MTLS"
    certificate       = file("pm-client.crt") # Platform Manager's client certificate
    private_key       = file("pm-client.key")
    truststore        = file("kafka-ca.crt")
  }
  topic_pattern                    = "{tenant}-{instance}-{environment}-{topic}"
  group_pattern                    = "{tenant}-{instance}-{environment}-{group}"
  transactional_pattern            = "{tenant}-{instance}-{environment}-{transactional.id}"
  bootstrap_urls_by_authentication = { MUTUAL_TLS = "kafka.example.com:9093" }
  ssl_auth_mode                    = "fullChainCertificate"
}
```

A SASL connection:

```hcl
resource "axual_cluster" "sasl" {
  name          = "test-cluster"
  provider_type = "apache-kafka"
  broker = {
    bootstrap_servers = "kafka-test.example.com:9094"
    protocol          = "SASL/SCRAM-SHA-512"
    username          = "platform-manager"
    password          = "YOUR_PASSWORD" # replace with the SCRAM password
    truststore        = file("kafka-ca.crt")
  }
}
```

## Import

Import is supported by ID, or by name (`name:`):

```shell
terraform import axual_cluster.<LOCAL NAME> <CLUSTER UID>
terraform import axual_cluster.production 3f2a1b0c9d8e7f6a5b4c3d2e1f0a9b8c
terraform import axual_cluster.<LOCAL NAME> name:<CLUSTER NAME>
terraform import axual_cluster.production 'name:production-ams'
```

The name must match exactly, case included. After importing, add the `private_key` or `password` to your configuration: Platform Manager does not return it.

In Terraform 1.12 or later, an `import` block can use `identity` instead of `id`:

```terraform
import {
  to = axual_cluster.production
  identity = {
    id = "3f2a1b0c9d8e7f6a5b4c3d2e1f0a9b8c"
  }
}
```
