# axual_application_deployment_state (Resource)

The desired running state of an Application Deployment: whether it should run or be stopped. Use it with an `axual_application_deployment` that has `autostart = false`, so the deployment (its target and configs) can be created before the principal, credential and access grant, the same order the Self-Service UI uses. Make this resource depend on the access grant approval and on the principal or credential. Create and update send START or STOP and wait for the deployment to get there. Every plan reads the real state, so a deployment that was stopped outside Terraform, or that has failed, shows up as a change and the next apply starts it again. Destroy stops the deployment and, for a Connector, resets it (removes the connector from its Connect cluster, keeping the deployment, its configs and its offsets), so the principal, credential and grant can be removed after it.

## Usage

- Use it with an [`axual_application_deployment`](application_deployment.md) that has
  `autostart = false`. With the default `autostart = true` the deployment resource starts the
  deployment itself, and the two resources would both decide whether it runs.
- `state = "RUNNING"` starts the deployment (or restarts a failed connector) and waits until it
  runs. `state = "STOPPED"` stops it.
- Every plan reads the real status. A deployment stopped outside Terraform shows `state` changing
  from `STOPPED` to `RUNNING`, and one that has failed from `FAILED` to `RUNNING`. For a Connector,
  a failed task counts as failed, even while Kafka Connect still reports the connector as running.
- `current_state` is the live status as Platform Manager reports it, for example `Running`,
  `Starting`, `Stopped`, `Failed` or `Undefined` for a Connector.
- Destroying this resource stops the deployment and, for a Connector, resets it: the connector is
  removed from its Connect cluster, and the deployment, its configs and its offsets stay. This is
  the state the deployment was created in, and it lets Platform Manager delete the connector's
  principal afterwards (it refuses to delete an active principal of a deployment that is only
  stopped).
- Make it depend on the access grant approval and on the principal or credential. See the
  [Connector Application guide](../guides/connector-application.md) for the complete order.

## Platform Manager version

| Deployment | Platform Manager |
|---|---|
| A `Connector` on Axual Connect | 15.0.x or later |
| A `Connector` on a registered Kafka Connect cluster | 16.0.0 or later |
| A `FLINK_SQL` deployment | 16.0.0 or later |

## Schema

### Required

- `application_deployment` (String) The Uid of the `axual_application_deployment` whose state this resource manages.
- `state` (String) The desired state: `RUNNING` or `STOPPED`. After a refresh this reads the state the deployment is really in, which is `FAILED` for a deployment that has failed, so drift shows up as a change back to the desired state.

### Read-Only

- `current_state` (String) The live status Platform Manager reports for the deployment, for example `Running`, `Starting`, `Stopped`, `Failed` or `Undefined` for a Connector.
- `id` (String) The Uid of the Application Deployment, the same as `application_deployment`.

## Example Usage

```hcl
resource "axual_application_deployment" "connector" {
  application    = axual_application.connector.id
  environment    = axual_environment.example.id
  target_id      = data.axual_connect_cluster.sasl.id
  target_version = "1.0.0"
  autostart      = false
  configs        = { /* ... */ }
}

resource "axual_application_credential" "connector" {
  application = axual_application.connector.id
  environment = axual_environment.example.id
  target      = "KAFKA"
  depends_on  = [axual_application_deployment.connector]
}

resource "axual_application_access_grant" "connector" {
  application = axual_application.connector.id
  topic       = axual_topic.example.id
  environment = axual_environment.example.id
  access_type = "CONSUMER"
  depends_on  = [axual_topic_config.example, axual_application_credential.connector]
}

resource "axual_application_access_grant_approval" "connector" {
  application_access_grant = axual_application_access_grant.connector.id
}

resource "axual_application_deployment_state" "connector" {
  application_deployment = axual_application_deployment.connector.id
  state                  = "RUNNING"
  depends_on = [
    axual_application_access_grant_approval.connector,
    axual_application_credential.connector,
  ]
}
```

## Import

Import is supported using the Application Deployment's Uid:

```shell
terraform import axual_application_deployment_state.<LOCAL NAME> <APPLICATION DEPLOYMENT UID>
terraform import axual_application_deployment_state.connector 362f33655195493c9574fc18f5d9a701
```
